# 旅行鹈鹕 · 全屏沉浸 v3.1

基于 travel_pelican_immersive_v3.html，修正“开始下一轮却一直是同一场景”的行为。
延续现有画风、六处场景、音源和计时胶囊。首次使用提供可收起的轻提示，日常主画面仍保持低干扰。

## 打开与使用

直接打开 index.html。请让 recorded-audio-assets.js 与 index.html 保持在同一目录，以便继续离线使用实录环境声。

新存档可从首次提示选择专注或自由陪伴；老用户不自动弹出提示。设置 → 偏好 → 怎样使用旅行鹈鹕，可重新查看。
计时胶囊显示专注、休息和暂停状态；声音准备、静音和恢复提示在操作附近显示，正常反馈会自动收起。
产品状态规则见 [EXPERIENCE.md](EXPERIENCE.md)，角色资产与动作约束见 [CHARACTER_GUIDE.md](CHARACTER_GUIDE.md)。

设置 → 旅行场景 → 随机场景。启用后，显式开始下一轮专注时，从已开放地点中选另一处。
若已有固定场景偏好，则继续保留。已选卡片会显示“已固定”；随机不会覆盖用户的固定选择。

第一次开始使用当前准备好的画面。暂停、继续、进入休息、结束休息但尚未开始下一轮、预览、切换工作窗口以及恢复未结束计时，都不重新抽景。

## 这次修正的原因

旧版 FocusTimer.startNext 仅调用 ensureForFocus；后者只有在旅行状态已经为 complete 时才开始下一段。
专注计时结束不意味着独立的 15–35 分钟旅行已经结束。短轮、提前结束或者尚未完成的长旅程会反复沿用同一场景。
此外，旧版在用户点击时没有先按真实时间结算旅行，到期状态可能仍等待 1 秒轮询刷新。

现在用户点击“开始下一轮”时，先在同一事务中结算已到期旅行、计算开放资格，再处理场景选择。
随机模式不会连续两轮选择同一地点（仅剩一个可用地点时除外）；新开放推荐也必须遵循此规则。

## 未完成旅行如何保存

换景不是完成旅行，不会立刻赠送照片或累计解锁次数。

例如桂林原定旅行 30 分钟，实际进行 10 分钟后开始下一轮并转到三亚：
桂林保存剩余 20 分钟和原先确定的照片结果；下次选到桂林时，从剩余 20 分钟继续。
暂停在其他目的地的旅行不会同时在后台推进。

每个目的地最多保留一段未完成旅行。只有当前活动目的地会计时。
休息和暂停专注不暂停旅行时钟，与此前“专注和旅行独立”的规则一致。
关闭网页后，最多结算离开时正在进行的那一段；不会补算多个离线旅程，不会计算离线专注时长。

## 场景开放与收藏

初始开放桂林、三亚、重庆；首次旅程 15 分钟，后续新旅程 15–35 分钟。
累计完成第 1／3／6 段时开放敦煌／洱海／西湖；可在预览中调整优先解锁顺序。
完成次数以已结算旅行为准，不依赖短番茄数量、刷新次数、音量、静音或动画开关。
已完成旅行仍产生一张照片，首次到访仍产生纪念章。各地点三种照片，共 18 张，收藏规则不变。

## 数据迁移

本次新日志键为 travel-pelican-journal-v3，内部 schema 为 3。
首次优先迁移 v3 页面产生的 travel-pelican-journal-v2（schema 2），保留原来的解锁状态、当前旅行、照片、纪念章和优先安排，不将全部用户误判为旧版六地全开。
没有上述数据时，才按原迁移规则处理旧版 schema 1。旧存储键不写入、不清空。

备份导出 version 3；导入支持 version 1／2／3。
导入合并照片、到访、开放资格、已结算标识、计时记录与不冲突的暂存旅行。
不替换当前正在进行的旅行、计时和声音偏好。本地音乐不在 JSON 备份中。

本地 file:// 页面能否共享存储取决于浏览器，聊天预览的新临时目录也可能形成独立的存储区域。
如新文件没有读到旧进度，请在旧文件“设置 → 记录与备份”导出，在新文件同一入口导入。无需清空任何旧数据。

## 首次加载、声音与发布

首页会先显示明确的旅行准备界面，场景完成绘制后再平滑进入；慢网络会更新阶段提示，等待超过 30 秒时提供“重新加载”。加载状态支持屏幕阅读器播报和“减少动态效果”。

实录环境声从首页拆分到同目录的 recorded-audio-assets.js：首页由约 10 MB 缩小到约 300 KB，主场景优先出现，五组环境声随后在后台准备。整套站点文件仍可离线播放环境声。
轻配乐开关默认开启，保留已保存的关闭或静音偏好。
默认完整配乐仍从作者官网加载；没有把在线配乐改成合成音乐。也能自行导入本地音乐。
音源和署名完全沿用上一版，见 AUDIO_CREDITS.md。

站点包可作为静态网页使用，并发布于 https://jarliao.github.io/pelican-bicycle/immersive-v3-1/ 。

## 角色资产一致性

骑行、休息和旅行照片中的鹈鹕保持暖白羽毛、长喙与喉囊、绿色头盔、赭色围巾等识别特征。
休息改为背身捧咖啡看风景：收圆的背部、后脑头盔与后扣，脸藏在远侧，仅露出透视缩短的喙。左翅折叠，右翅承托咖啡杯，围巾自然垂落，小桌只留杯碟。
长凳靠背位于角色近侧，遮住下背；身体落在座面上，短腿垂在远侧。接触阴影和前后遮挡共同表达坐姿。
呼吸动画以腹部下沿为支点，腿与长凳保持稳定；“减少动态效果”或静止画面设置会停止动画。旅行册休息照片与主场景复用同一姿态。
角色一致性约束识别特征、配色和画风，允许躯干、颈部、表情及肢体随动作改变。背面头部在共享的 `pelican-back-head` 中维护，主场景和照片均通过 `COMPONENTS.rest` 复用；骑行造型不变。
